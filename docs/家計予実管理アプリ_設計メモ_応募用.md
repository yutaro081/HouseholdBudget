# 家計・予実管理アプリ 設計メモ（応募用）

## 1. 開発の目的

経理実務で感じていた、

- 日々の取引入力に手間がかかる
- 記録したデータが後から十分に活用されにくい
- 予算・実績・残高・資金繰りの確認が分散しやすい
- 異常値や入力漏れに気づきにくい

という課題を、JavaのWebアプリとして整理・改善することを目的にする。

単なる家計簿ではなく、

> 経理業務の考え方を活かし、取引入力から集計・予算・残高確認までをつなげる業務改善型Webアプリ

として制作する。

---

## 2. ポートフォリオとして見せたいこと

このアプリでは、単に「Javaが使える」ことだけでなく、以下を伝える。

- 会計・経理の知識
- 業務上の課題発見
- 要件整理
- 画面・DB設計
- MVC / DAO / JDBCを使った実装
- 集計・予実管理
- 業務改善の考え方
- エラーや課題を自分で調べて修正した経験
- 将来の拡張を考えた設計

## 8. 予算管理

### 実装したい内容

- 科目別予算
- 実績
- 残予算
- 予算消化率
- 月経過率との比較
- 危険水域アラート

例：

```text
食費
予算      30,000円
実績      24,000円
残予算     6,000円
消化率        80%
月経過率      50%

→ 支出ペースが速い
```

---

## 9. 残高管理

主に現預金を対象にする。

### 月別残高一覧

```text
月       月初残高    収入      支出      月末残高
6月      150,000    80,000    65,000    165,000
7月      165,000    80,000    72,000    173,000
```

基本式：

```text
月末残高 = 月初残高 + 収入 - 支出
```

---

## 10. 資金繰り

将来的には、今後予定される入出金も含めて残高を予測する。

例：

```text
現在残高       200,000円

10/10 カード   -52,000円
10/15 通信費    -8,000円
10/25 給与     +180,000円

予測残高       320,000円
```

---

## 11. 異常値・入力漏れチェック

残高や取引内容から、不自然なものを検知する。

例：

- 同じ日・同じ金額・同じ摘要の重複
- 現金残高がマイナス
- 過去平均より大幅に高い支出
- 前月比で急増した科目
- クレジットカード利用額と引落予定額の不一致
- 残高推移の異常な増減

## 13. 将来的な自動仕訳

ユーザーは簡単な入力だけ行い、内部では会計的な記録を作る。

例：

```text
スーパー 2,980円
支払方法：現金
```

内部：

```text
食費 2,980 / 現金 2,980
```

クレジットカードの場合：

```text
食費 2,980 / カード未払 2,980
```

引落時：

```text
カード未払 2,980 / 普通預金 2,980
```

- 支出構成の変化
- 増えた関心

## 17. アプリの思想

> 記録するための家計簿ではなく、記録を価値に変える家計簿

支出は単なるコストではなく、

> その人が何を大切にし、何を生み出そうとしているかを表す記録

でもある。

最終的には、

- 入力は最小限
- 一度入力したデータを複数用途に活用
- 記録が増えるほど新しい発見が生まれる
- 本人の価値観に沿った判断を支援する

ことを目指す。
